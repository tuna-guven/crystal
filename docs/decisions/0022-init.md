# 0022 --init: check and ask first, create last, undo on failure

- **Date:** 2026-11-06 (#14)
- **Status:** Accepted

## Context

`crystal --init` creates a vault directory, four files, a config entry and
two rollback counters, and asks for a passphrase and backup recipients on
the way. A half-made vault (a directory without `identity.backup.age`, or
a vault the config does not know) is confusing at best and unrecoverable
at worst.

## Decision

- **Order:** resolve and check the target; ask for the passphrase (and
  refuse a name already in the config); ask for backup recipients; only
  then create anything. Cancelling any prompt leaves nothing behind.
- **Target:** `~/Vaults/NAME` by default, with `HOME` resolved so the
  stored path has no symlink. `--at DIR` names the vault directory itself,
  which must not exist (approved 2026-11-06). Its parent must pass the
  vault path walk ([0020](0020-vault-path-checks.md)) and be a safe
  parent itself. A missing `~/Vaults` is created with mode 0700.
- **Backup recipients:** one or more `age1…` public keys, typed on the tty
  and echoed (they are public), validated by age, re-asked when invalid;
  not taken from argv (approved 2026-11-06). At least one is required, at
  most eight.
- **Creation:** `VERSION`, a new identity and random `vault_id`,
  `identity.age`, `identity.backup.age`, an empty `vault.age` at
  generation 1, each through the atomic writer; then the full vault check
  on the result, the config entry, `config.age`, and the vault's counter.
- **Undo:** if a creation step fails, the files, the vault directory and a
  `~/Vaults` made by this run are removed, and the error says so. A
  directory that existed before is never removed. A failure to write
  `config.gen` after `config.age` was written leaves the complete,
  registered vault in place.

## Alternatives

- **Create the directory first, then prompt:** a cancelled prompt leaves
  an empty or partial vault.
- **Backup recipients on the command line:** shell history, and a larger
  flag list; they are public, but argv is the wrong place for anything
  typed by hand.
- **No backup recipient:** losing the passphrase would lose the vault.
- **`--at DIR` as the parent:** `--at ~/Sync` would silently create
  `~/Sync/NAME`, which is easy to misread.

## Consequences

- Every Crystal vault has an offline recovery path from the start.
- `--init` on a new device costs two scrypt operations (identity, config);
  on a device with a config, three (unlock the config first).
- The backup key's secret half must be kept off the machine by the user;
  Crystal cannot check that.
