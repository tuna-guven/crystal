# Threat model

Crystal defends notes at rest and during use against storage, sync, theft and malicious content; it does not defend against root, kernel compromise or a hostile terminal emulator.

**Assets:** note content; note metadata (titles, links, tags, note count, sizes); vault names (the directory names in `~/.local/share/crystal`); the vault identity key; the user's passphrase or hardware key.

| Adversary | Capability | Scope | Primary defense |
| --- | --- | --- | --- |
| A1 Storage or sync attacker (cloud, Syncthing peer, stolen backup) | Read, modify, delete, reorder, roll back ciphertext files | In | age AEAD over the whole vault, embedded vault\_id, generation counter, Padmé padding; the vault's recipient kept private, since age does not authenticate the writer ([0044](../decisions.md#0044)); against offline guessing of a copied `identity.age`, a passphrase of at least 20 characters ([0028](../decisions.md#0028)) under scrypt log N 20 ([0066](../decisions.md#0066)); no second way in, such as a recovery code ([0064](../decisions.md#0064)); if a passphrase may have leaked, `crystal passwd` changes the vault key with it, so a copied `identity.age` opens nothing saved afterwards ([0065](../decisions.md#0065)) |
| A2 Device thief, machine off | Full disk read | In | No plaintext ever written; full-disk encryption assumed as a second layer |
| A3 Malicious note content (imported, synced, pasted) | Terminal escape injection, parser bugs; a link whose text hides where it goes | In | Sanitizer on every text node, which spells hidden characters out as `<U+XXXX>` ([0037](../decisions.md#0037)), fuzzed parser and renderer, sandbox limits impact; a clickable link's target is only http, https or mailto in URI characters, checked three times before it enters an OSC 8 sequence. Accepted: a clickable link hides its address, so its text can name another site ([0054](../decisions.md#0054)) |
| A4 Supply chain (malicious or compromised crate) | Arbitrary code in the process | In | Minimal deps, each reviewed when added and pinned exactly where it sees secrets or hostile input; `cargo deny` and `cargo audit`; from before the first passphrase prompt, Landlock (only this vault and the state directory; no TCP, no pathname or abstract UNIX sockets, no signals out) and a seccomp allowlist (no `socket`, `exec`, threads, `ptrace`, `io_uring`); from exec on, the SELinux domain `crystal_t` ([Sandboxing](sandboxing.md), [0059](../decisions.md#0059), [0061](../decisions.md#0061)). Code running before the sandbox (startup steps 1 to 7) is confined by SELinux only |
| A5 Same-user malware, vault locked | Read files, log keystrokes, replace or shadow `~/.local/bin/crystal`, change the pin and rollback counters | Partial | Notes stay encrypted; hardware key with touch defeats passphrase logging; once the malware is gone, `crystal passwd` makes a logged passphrase and a copied `identity.age` useless for later saves ([0065](../decisions.md#0065)); optional immutable binary ([Installation](../guide/installation.md)); no config file, vaults only in one fixed, checked place ([0032](../decisions.md#0032)) |
| A6 Same-user malware, vault unlocked | ptrace, /proc reads, screen capture, reading the system clipboard | Partial | Non-dumpable process blocks ptrace and /proc/pid/mem; the sandbox also keeps a compromised Crystal from reaching other processes (Landlock's signal and socket scopes, seccomp, `crystal_t`); screen capture not preventable; Crystal never writes to the system clipboard, so note text reaches it only when the user copies with the terminal's selection ([0041](../decisions.md#0041)) |
| A7 Root, kernel exploit, cold boot, evil maid | Everything | Out | Handled at OS level (verified boot, TPM, hardened kernel) |
| A8 Shoulder surfing, screen recording | Sees the screen | Out | Idle auto-lock reduces exposure |
| A9 Someone who finds an old recovery code (paper) | Opens a copy of an older vault that still holds `identity.backup.age`, with any age tool | Partial | Crystal makes no code any more ([0064](../decisions.md#0064)); the setup guide says to delete `identity.backup.age` by hand and destroy the paper. Copies already in backups or on other devices still open with the code |

**Trust boundaries:** the kernel; the terminal emulator (it receives every rendered character, and must keep pasted text from ending a bracketed paste early: Ptyxis 50.1 on VTE 0.84.1 pastes ESC as `␛`, checked 2026-11-14, [decision 0047](../decisions.md#0047)); Crystal's age code (`age_v1`, ported from rage's library and checked against the C2SP/CCTV vectors) and the RustCrypto and dalek primitives under it ([decision 0042](../decisions.md#0042)); the compiled binary and its build chain; the installed copy in `~/.local/bin`, which is user-writable unless marked immutable ([Installation](../guide/installation.md)).

**Security properties Crystal guarantees**

- Confidentiality of note content and titles at rest
- Integrity of each note and of the vault as a set (no swapped, injected or deleted notes go unnoticed); a forged vault needs the vault's recipient, which never leaves the device ([0044](../decisions.md#0044))
- Rollback detection relative to the newest state this device has seen ([Storage, Rollback](storage.md#rollback)); an older vault opens only after you type `restore` ([0036](../decisions.md#0036)); a same-user process (A5) can lower the plaintext counters, which is accepted
- No plaintext persisted by Crystal itself, including on crash

**Accepted leaks:** the vault's Padmé size bucket and when it was last saved. Note count, note sizes and which note changed stay hidden.
