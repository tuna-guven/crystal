# Startup order and process hardening

Hardening happens in a fixed order: protections that cost nothing go first, and the sandbox locks down before the passphrase is asked, so every file Crystal parses at unlock (`identity.age`, `vault.age`) is parsed inside it ([decision 0059](../decisions.md#0059)). The detailed sandbox design (Landlock rules, seccomp policy, SELinux module, bubblewrap launcher, verification) is in [Sandboxing](sandboxing.md).

1. Install the panic hook (restore terminal, print location only).
2. `setrlimit(RLIMIT_CORE, 0)`, `prctl(PR_SET_DUMPABLE, 0)`, `prctl(PR_SET_NO_NEW_PRIVS, 1)`, `umask(0o077)`. Then refuse to start if any fd above 2 is open (read from `/proc/self/fd`). Landlock does not restrict fds opened before it and seccomp allows `read` and `write`, so an inherited socket or directory fd would bypass the sandbox, and the age plugin would inherit it too. Crystal cannot close an fd it does not own without `unsafe` (rustix has no safe `close_range`), so it fails closed.
3. Environment allowlist: read only `HOME` (must be absolute; locates the vault, state and settings directories), `TERM`, `COLORTERM`, locale variables, through `harden::env_var`, which takes an `EnvVar` enum with one variant per allowed variable; never read `EDITOR`, `PAGER`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME` or similar. Clippy's `disallowed-methods` (clippy.toml) makes any other `std::env` read a build error. The process environment is not modified (`remove_var` is `unsafe` in edition 2024 and the crate forbids `unsafe`); instead, the only child process, the age plugin, is spawned with `env_clear()` plus the allowlist.
4. `mlockall` with `MCL_CURRENT | MCL_FUTURE | MCL_ONFAULT`, after raising the soft `RLIMIT_MEMLOCK` to the hard limit. Refuse to continue if the hard limit is below 512 MiB (a smaller budget can run out mid-session, and the failed allocation aborts without zeroizing or saving) or if `mlockall` fails, with a message pointing to [Setup](../guide/setup.md).
5. Require a real tty; open `/dev/tty` directly for input and output.
6. Parse args in the `cli` module: always a command word first ([decision 0032](../decisions.md#0032), [decision 0058](../decisions.md#0058)): `crystal unlock NAME`, `crystal init NAME`, `crystal recover NAME`, `crystal check-code NAME`, `crystal rm NAME`, `crystal help`; a bare `crystal NAME` is refused. NAME is 1 to 64 characters from `A-Z a-z 0-9 - _`, starting with a letter or digit, and not one of the older command words (`init`, `rm`, `recover`, `check-code`, `help`), so no `/`, `..`, hidden names or option look-alikes; `-h`/`--help`. Anything else is refused. Errors are fixed messages that never echo an argument, since a mistyped argument could be a passphrase; lexopt's own errors are discarded because they quote the argument.
7. Open `~/.local/share/crystal/NAME` and the state directory as directory fds with `O_DIRECTORY` and `O_NOFOLLOW`, each reached one component at a time from `HOME` ([Storage, Vault directory](storage.md#vault-directory)): `.local`, `share` and `state` must be ours and not group- or world-writable; `crystal`, the vault directory and the state directory must be ours and mode 0700. Only `crystal init` creates `~/.local/share/crystal` or a vault directory. Read the vault's `VERSION` ([decision 0034](../decisions.md#0034)) and refuse a `vault.sync-conflict-*.age` (resolved by hand: keep one version; nothing is merged, [decision 0045](../decisions.md#0045)). Then enter raw mode and the alternate screen on the `/dev/tty` fd (terminal guard), so the passphrase prompt is drawn there.
8. Apply Landlock ([Sandboxing](sandboxing.md) section 5) through the `landlock` crate, up to ABI 9: read and write only beneath the vault and state directories, whose fds from step 7 are the rule fds, so other vaults stay unreachable during a session; deny TCP bind and connect; block pathname Unix sockets (`RESOLVE_UNIX`); scope signals and abstract Unix sockets. The ruleset uses the crate's hard-requirement mode, so a right the kernel cannot enforce is an error. Below ABI 9, or without Landlock, Crystal refuses to start; there is no weaker mode and no override flag.
9. Apply seccomp (allowlist, below; [Sandboxing](sandboxing.md) section 6), with kill-process as the default action. From here on `execve` is denied.
10. Unlock, inside the sandbox ([decision 0059](../decisions.md#0059)): ask once for the passphrase, open `identity.age` and wipe the passphrase. `crystal recover` and `crystal check-code` take steps 8 to 10 the same way before their prompt; `crystal init` and `crystal rm` never enter the sandbox and exit. A hardware-key plugin (Phase 8) needs `execve`; how such a vault unlocks is decided then.
   - *As built (`unlock.rs`, [decision 0023](../decisions.md#0023), [decision 0032](../decisions.md#0032)):* steps 8 and 9 run in `main` right before the welcome prompt (`harden::enter_sandbox`, Phase 6 steps S3 to S5), so steps 10 and 11 and the Crystal shell ([decision 0033](../decisions.md#0033)) run inside both layers. `crystal recover` and `crystal check-code` enter the sandbox right before the recovery code prompt (step S8); `check-code` gets the vault directory only, no state directory.
11. Decrypt `vault.age` (parsing it inside the sandbox); require the `vault_id` pinned in `NAME.pin` (or pin it on the first unlock on this device); check the generation counter, and for an older vault ask for `restore` ([decision 0036](../decisions.md#0036)), quitting with nothing accepted after 5 minutes without a key ([decision 0048](../decisions.md#0048)); build the indexes (names, links, tags) and enter the Crystal shell ([decision 0033](../decisions.md#0033)).

**Seccomp allowlist:** the 23 syscalls in [Syscalls, The allowlist](../reference/syscalls.md#the-allowlist), with argument rules for `ioctl`, `fcntl`, `kill`, `prlimit64` and `mmap` ([Sandboxing](sandboxing.md) section 6). Everything else kills the process.

**Explicitly denied:** `socket`, `socketpair`, `connect`, `bind`, `execve`, `execveat`, `ptrace`, `process_vm_readv`, `process_vm_writev`, `bpf`, `io_uring_setup`, `io_uring_enter`, `io_uring_register`, `userfaultfd`, `perf_event_open`, `keyctl`, `add_key`, `mount`, `unshare`, `setns`, `personality`, `memfd_create`, `clone`, `clone3` (Crystal is single-threaded), and the `ioctl` requests `TIOCSTI` and `TIOCLINUX`.

Collect the real syscall set as [Sandboxing](sandboxing.md) section 6 describes: the test suites with the log action as a local, never-committed change, then `run0 ausearch -m SECCOMP -c crystal -i`. Every build kills on a syscall outside the list; there is no log build. Crystal is single-threaded: if a dependency starts a thread, that is a finding to fix, not a reason to allow `clone`.

**System-level recommendations:** encrypted swap or zram only, hibernation disabled, Yama `ptrace_scope` at 1 or higher, full-disk encryption, and a terminal emulator without disk-backed scrollback.
