# Startup order and process hardening

Hardening happens in a fixed order: protections that cost nothing go first, unlock happens while exec is still possible (for hardware-key plugins), and the sandbox locks down before any note is decrypted or rendered. The detailed sandbox design (Landlock rules, seccomp policy, SELinux module, bubblewrap launcher, verification) is in [Sandboxing](sandboxing.md).

1. Install the panic hook (restore terminal, print location only).
2. `setrlimit(RLIMIT_CORE, 0)`, `prctl(PR_SET_DUMPABLE, 0)`, `prctl(PR_SET_NO_NEW_PRIVS, 1)`, `umask(0o077)`. Then refuse to start if any fd above 2 is open (read from `/proc/self/fd`). Landlock does not restrict fds opened before it and seccomp allows `read` and `write`, so an inherited socket or directory fd would bypass the sandbox, and the age plugin would inherit it too. Crystal cannot close an fd it does not own without `unsafe` (rustix has no safe `close_range`), so it fails closed.
3. Environment allowlist: read only `HOME` (must be absolute; locates the config, state and default vault directories), `TERM`, `COLORTERM` and locale variables, through `harden::env_var`, which takes an `EnvVar` enum with one variant per allowed variable; never read `EDITOR`, `PAGER`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME` or similar. Clippy's `disallowed-methods` (clippy.toml) makes any other `std::env` read a build error. The process environment is not modified (`remove_var` is `unsafe` in edition 2024 and the crate forbids `unsafe`); instead, the only child process, the age plugin, is spawned with `env_clear()` plus the allowlist.
4. `mlockall` with `MCL_CURRENT | MCL_FUTURE | MCL_ONFAULT`, after raising the soft `RLIMIT_MEMLOCK` to the hard limit. Refuse to continue if the hard limit is below 256 MiB (a smaller budget can run out mid-session, and the failed allocation aborts without zeroizing or saving) or if `mlockall` fails, with a message pointing to [Setup](../guide/setup.md).
5. Require a real tty; open `/dev/tty` directly for input and output.
6. Parse args in the `cli` module: a command word first, if any ([decision 0024](../decisions/0024-subcommands.md)): `crystal init NAME [--at DIR]`, `crystal add NAME DIR`, `crystal remove NAME`, `crystal help`; otherwise one vault name to open (1 to 64 characters from `A-Z a-z 0-9 - _`, starting with a letter or digit, and not a command word, so no `/`, `..`, hidden names, option look-alikes or ambiguity), `--lock-after MINUTES` (default from the config, else 5; range 1 to 1440), `-h`/`--help`; from Phase 6 also `--sandbox-status`. Anything else is refused. Errors are fixed messages that never echo an argument, since a mistyped argument could be a passphrase; lexopt's own errors are discarded because they quote the argument.
7. Open `~/.config/crystal` and the state directory as directory fds with `O_DIRECTORY` and `O_NOFOLLOW`, and check that each is ours and mode 0700. The state directory is reached one component at a time from `HOME` with `O_NOFOLLOW`; `.local` and `state` must be ours and not group- or world-writable. The config directory is created (0700) only by `crystal init` or `crystal add`, never as a side effect of opening. Then enter raw mode and the alternate screen on the `/dev/tty` fd (terminal guard), so the passphrase prompt is drawn there.
8. Unlock: decrypt `config.age` with a passphrase or an age plugin, and reject it if its generation is older than `config.gen`. Look up the vault name, and open the vault path with the checks under [Config file](storage.md#config-file) (the vault directory itself must be ours and mode 0700, even inside `~/Vaults`). Decrypt that vault's `identity.age` (same passphrase, or another plugin touch). Close the config fd. The vault and state fds are later reused as the Landlock rule fds, so other vaults and the config stay unreachable during a session. Plugins are external binaries, so this is the last moment `execve` is allowed.
   - *As built (`unlock.rs`, [decision 0023](../decisions/0023-unlock.md)):* without a `config.age`, Crystal refuses before asking anything. Otherwise it asks once for the passphrase, then: decrypt `config.age` and check `config.gen`; find the name; walk and check the vault path; refuse a `vault.sync-conflict-*.age` (the per-note merge is #31); read `VERSION`; open `identity.age`; decrypt `vault.age`; require the pinned `vault_id`; check and update the vault's generation counter. The passphrase is wiped as soon as the identity is open, and the config fd is closed before anything else happens. Until the TUI (Phase 3), a placeholder screen shows only the number of notes.
9. Apply Landlock ([Sandboxing](sandboxing.md) section 5) through the `landlock` crate, up to ABI 9: read and write only beneath the vault, state and external backup directories (never the config directory); deny TCP bind and connect; block pathname Unix sockets (`RESOLVE_UNIX`); scope signals and abstract Unix sockets. The ruleset uses the crate's hard-requirement mode, so a right the kernel cannot enforce is an error. Below ABI 9, or without Landlock, Crystal refuses to start; there is no weaker mode and no override flag.
10. Apply seccomp (allowlist, below; [Sandboxing](sandboxing.md) section 6), with kill-process as the default action. The log action exists only in builds with the `sandbox-audit` feature, never in release.
11. Decrypt the vault, build the index, enter the TUI.

**Seccomp allowlist (starting point):** `read`, `write`, `openat`, `close`, `fstat`, `newfstatat`, `statx`, `lseek`, `getdents64`, `mkdirat`, `renameat2`, `unlinkat`, `fsync`, `fdatasync`, `mmap`, `munmap`, `mremap`, `mprotect` (deny `PROT_EXEC`), `brk`, `madvise`, `rt_sigaction`, `rt_sigprocmask`, `rt_sigreturn`, `sigaltstack`, `ioctl` (only `TCGETS2`, `TCSETS2`, `TCSETSF2`, `TIOCGWINSZ`: rustix uses the `*2` termios requests and falls back to `TCGETS` only on an error return, which a seccomp kill never gives; see [Syscalls](../reference/syscalls.md)), `poll`, `ppoll`, `epoll_*`, `clock_gettime`, `clock_nanosleep`, `futex`, `getrandom`, `getpid`, `kill` (own pid only, `SIGSTOP`, to suspend on Ctrl+Z or `SIGTSTP`), `exit`, `exit_group`.

**Explicitly denied:** `socket`, `socketpair`, `connect`, `bind`, `execve`, `execveat`, `ptrace`, `process_vm_readv`, `process_vm_writev`, `bpf`, `io_uring_setup`, `io_uring_enter`, `io_uring_register`, `userfaultfd`, `perf_event_open`, `keyctl`, `add_key`, `mount`, `unshare`, `setns`, `personality`, `memfd_create`, `clone`, `clone3` (Crystal is single-threaded), and the `ioctl` requests `TIOCSTI` and `TIOCLINUX`.

Develop with the `sandbox-audit` feature (log action), run every feature, and collect the real syscall set from the audit log with `run0 ausearch -m SECCOMP -c crystal`; this works with secureblue's `deny_ptrace` on. `strace -f -c` also works where ptrace is allowed. Then switch to kill. Crystal is single-threaded: if a dependency starts a thread, that is a finding to fix, not a reason to allow `clone`.

**System-level recommendations:** encrypted swap or zram only, hibernation disabled, Yama `ptrace_scope` at 1 or higher, full-disk encryption, and a terminal emulator without disk-backed scrollback.
