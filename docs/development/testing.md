# Testing and verification

Integration tests drive the real binary in a pseudo-terminal (`script`); their shared helpers are in `tests/common/mod.rs`. Tests of the shell and pager open a vault and add sample notes in memory with the debug-only flag `--demo-notes-for-test` (not in release builds, so those tests are ignored there; nothing is saved: the editor's Ctrl+S is refused in such a session, `demo_notes_are_never_saved`). Tests of the editor and of saving create real notes with `new` instead. Tests of startup steps 1 to 7, signals and the terminal guard pass the debug-only `--skip-unlock-for-test`, so they need no vault; release builds have no such flag: `cli::tests::release_refuses_the_test_hooks`, which exists only in release builds, checks that every debug-only flag is an unknown argument there (`--lock-after-for-test` too, so auto-lock stays at 5 minutes; [decision 0048](../decisions.md#0048)). Under `cargo test --release`, the tests that need a debug-only hook are reported as ignored; everything else, including the tamper suite, runs against the release binary. Run it at the 512 MiB memlock floor too (`prlimit --memlock=536870912:536870912 cargo test --release`): only that run shows that the release binary's scrypt (log N 20, the same as every build; [decision 0027](../decisions.md#0027)) fits in locked memory with everything else. Debug and test builds optimize the scrypt crates (`[profile.dev.package.*]` in Cargo.toml) so the integration tests stay fast.

Each security property gets a test that would fail if the property broke; tests run in CI on every commit.

| Test | What it proves | Tooling |
| --- | --- | --- |
| Property tests | Round trips (codec, padding, encryption); the editor's undo and redo restore every text exactly, its grapheme steps land on boundaries, any key sequence keeps its cursor and selection inside the text on grapheme boundaries, and its screen draws the cursor exactly once and spells out every hidden character, invisible ones inside a visible grapheme included (only an emoji keeps its joiner and U+FE0F); a name `new` accepts comes back exactly as typed; any sequence of saves, each failing at any step of the atomic writer or not at all, leaves memory equal to the vault (a save that reports nothing saved changed neither; 32 cases, as each opens a vault); the renderer, sanitizer, wrapping, names and key decoding never panic, never put a control or BiDi character on screen and never draw a line wider than the page | `proptest`: 256 cases per test on every `cargo test`; `scripts/long-tests.sh` runs a million per test for the text-handling modules and Crystal's age code (`age_v1`: round trips, flipped bits, truncation and extension, random input; about 21 minutes in all), weekly in CI (`.github/workflows/long-tests.yml`) and before releases |
| Tamper suite | A vault swapped in under another's name (pin), truncation, bit flips: all refused; an older generation opens only after the word `restore`, and anything else changes nothing | `tests/vault.rs`: each test makes a vault with `crystal init` through the real binary in a pty, damages one thing (vault or config truncated, bit-flipped, rolled back or swapped, a wrong passphrase, a missing `identity.age`, a writable parent, a sync conflict copy) and checks the fixed refusal |
| Coverage-guided fuzzing | No panic, hang, unbounded memory or overflow (debug assertions on) on hostile Markdown, text, age files or vault bytes, beyond what random generation reaches; an age round trip gives the same text back, and a damaged valid file never opens as other text | `fuzz/`, its own workspace ([decision 0062](../decisions.md#0062)): targets `render`, `sanitize`, `age`, `vault` on `crystal::fuzz` (`cfg(fuzzing)` only). Run from the root on the pinned stable toolchain: `cargo fuzz run --sanitizer none --release --debug-assertions TARGET -- -max_total_time=3600`. First hour, 2026-11-16, all four in parallel, clean: render 5.7 M runs, sanitize 58 M, age 5.6 M, vault 696 M; peak memory 68 MiB. The corpora stay local (`fuzz/.gitignore`); there is no CI run (S0 skipped) |
| age v1 conformance | Crystal's own age code ([decision 0042](../decisions.md#0042)) reads and refuses files exactly as the reference implementations do, and what it writes is plain age | `tests/corpus/age-cctv/`: the C2SP/CCTV age vectors, unchanged (`scripts/import-cctv.sh`, pinned commit); `age_v1::cctv::cctv_age_vectors` runs the 92 for X25519, scrypt, the header and STREAM (armored and hybrid skipped) and re-encodes headers and payloads with the vectors' file keys. `tests/corpus/age-rage/`: files the `age` crate 0.11.5 wrote before step C3 removed it ([decision 0043](../decisions.md#0043); keys, passphrases and plaintext SHA-256 in `keys.txt` and `MANIFEST`, the generator in `SOURCE`): X25519 to one and three keys with age's grease, 0 bytes to 3 × 64 KiB, and scrypt identity files. `age_v1::rage` opens each with its keys and refuses strangers and wrong passphrases, and, under the unwrapped file key, re-encodes each file's stanzas (age's own, re-serialized), header MAC and STREAM payload to age's bytes; new stanzas cannot be compared byte for byte (their share or salt is random), so `wrap` is covered by the `wrapping_key` it shares with the checked `unwrap` and by the round trips; the `x25519`, `scrypt`, `header` and `crypto` tests use the same files. `age_v1::tests::round_trips_*` covers the same sizes and 32 MiB with Crystal alone (32 MiB is ignored in debug builds, a minute of unoptimized ChaCha20, and runs under `cargo test --release`). Integration tests check the real binary's files with its own commands (`init`, unlock). By hand, once, 2026-11-09: Go age v1.3.2 opened a vault the binary wrote, and the binary unlocked a vault Go age wrote; no script repeats it |
| Escape-injection corpus | OSC 52, OSC 8, title changes, CSI, DCS, APC, 8-bit C1, BiDi, NUL, zero-width and overlong lines, in every Markdown context, render inert; hostile link targets (raw, as entities, in angle brackets, as references) are never clickable | `tests/corpus/escape/`: `md::render::tests::escape_corpus` checks every cell and every clickable link's target and compares with golden files (`UPDATE_GOLDEN=1` to accept a deliberate change) |
| Clickable links | Only `md::link::clickable` targets reach the terminal, inside OSC 8, and every link is closed before the frame ends ([0054](../decisions.md#0054)) | `md::link` unit and property tests; `ui::frame::tests::written_links_are_always_safe_and_closed` (random targets, also forced past the grid's check); `only_clickable_targets_reach_the_terminal` (tests/vault.rs, through the binary). By hand, as CI cannot click: `scripts/check-links.sh VAULT`, which shows that Ctrl+click in Ptyxis opens the good link and nothing for the refused ones |
| Disk leak test | Inside the vault only ciphertext is written, and nothing else but the terminal (`/dev/pts`) (Phase 4 acceptance) | `strace_shows_only_ciphertext_written` (tests/vault.rs): `strace -f -yy -xx` over every write-family syscall (open, write and its vector and positional forms, sendfile, splice, rename, unlink, link, mkdir, truncate, fallocate) of a `new`, type, Ctrl+S session; every file opened for writing must be an atomic-writer temp file, only `write()` may reach a file, `mkdirat` may only find the state directory's levels already there, and each file's bytes, checked whole, must be an age file without the typed title or text canary in the vault, and only digits in the counter. Crystal is non-dumpable, so strace reads its bytes only with `CAP_SYS_PTRACE` (without it, it prints addresses) and its fd paths only with `CAP_DAC_READ_SEARCH` (its `/proc/PID/fd` is root's, mode 0500; without it, strace prints bare fd numbers); either way the test says so instead of passing unchecked. The test is therefore `#[ignore]`d and runs in CI only, which gives strace both capabilities (`setcap`) and runs it with `--ignored`; on secureblue it is not run (`deny_ptrace` stays on). Crystal itself gets no capability and keeps all of its hardening. `new_note_is_saved_and_opens_again` checks the finished files without strace |
| Crash during a save | `kill -9` at any moment of a save leaves a vault that opens, at the old or the new generation, with the counter never ahead (Phase 4 acceptance) | `kill_9_during_saves_never_corrupts_the_vault` (tests/vault.rs): at least 12 rounds of 300 saves, killed 0 to 330 ms after they start, and more (up to 60) until a kill has landed between the atomic writer's temp file and its rename, which a temp file left behind proves; about 40 s (here 4 of 12 kills land mid-write) |
| Sandbox | Inside the sandbox (entered before the passphrase prompt, [decision 0059](../decisions.md#0059)) a file outside the vault cannot be read or created, another vault is unreachable, and `/proc/PID/status` shows no new privileges and one seccomp filter; the memory stays unreadable; `socket`, `socketpair`, threads, `memfd_create`, `mkdirat`, other `ioctl` requests, signals to other processes and `exec` die by `SIGSYS`, and Landlock alone still refuses TCP, pathname UNIX sockets, directories, signals and `exec`; without Landlock, Crystal refuses to start before any prompt ([Sandboxing](../design/sandboxing.md) section 9). Needs Landlock ABI 9 or newer; runs locally (CI, roadmap step S0, skipped) | `tests/sandbox.rs`, through the debug-only `--sandbox-check-for-test CHECK`; one process per check |
| Canary scan | After lock, a unique canary string from a note, and the vault key's text form (`AGE-SECRET-KEY-1…`), no longer exist in process memory (Phase 5 acceptance) | `no_note_text_in_memory_after_lock` (src/session.rs): runs Crystal's parts as a session uses them, in a fresh process of the test binary, started alone so it is dumpable (Crystal itself is non-dumpable from its first lines, so even it cannot open its own `/proc/self/mem`, which then belongs to root, mode 0600). The child saves a note holding the canary in its title, its text, a heading, a tag and a link; fills the shell's completion names and types `search CANARY` into the shell key by key (its line, history and output); renders the pager and the editor, types into the editor and copies into Crystal's clipboard; then does what `lock` does, step by step as `app::run` and `crystal::run` (src/lib.rs) do it. It then reads every writable mapping through `/proc/self/mem` (an unmapped page is an error, never a crash). The canary and the key are only ever held XOR-masked by the test, so the search cannot find itself; before the lock the scan must find the live canary. Mutation-checked: a deliberately freed plain copy is found without the zeroizing allocator's wipe and gone with it, and a leaked copy of the shell's history entry is found. What it cannot see (accepted 2026-11-14, documented rather than more test code): text in the screen grids, since each cell holds one character next to its width and style, so a canary never lies in one piece there (grids are dropped at lock and freed memory is wiped; a grid kept alive would go unnoticed); the top of the stack, which the scan's own calls overwrite before reading it, so only residue deeper than they reach is found; and the loop itself (`app::run`, the terminal, the frame writer), since the lock steps are repeated by hand: the pty tests check what a lock does, not memory |
| Hardening checks | Non-dumpable, no core, memory locked, no new privs | Integration test reading `/proc/self/status` |
| Unsafe code | The allocator is sound: every freed block, and the old block of every realloc, is zeroed before the system allocator gets it back | `zalloc` tests in every `cargo test`: a wrapped allocator checks that each block is zero when it is freed (sizes 1 to 100 003 bytes, alignments 1 to 64, growing and shrinking reallocs), and `wipe` covers exactly its range at every start offset and length around a word; the canary scan, which CI runs in debug and release builds. Miri is not used: it needs a nightly toolchain |
| Dependency audit | No known vulnerabilities, only allowed licenses and sources, no banned crates; each crate reviewed by hand when added ([Dependencies](../design/dependencies.md)) | `cargo audit` and `cargo deny` before every commit and in CI, also in `fuzz/`; a release binary with `cargo audit bin` (its embedded list, [decision 0068](../decisions.md#0068)); `cargo vet` and `cargo geiger` are not set up |
| Reproducibility | Same source gives the same binary, which holds no home path or user name ([decision 0067](../decisions.md#0067)) | `packaging/check-reproducible.sh`: two clean clones of `HEAD` in different directories, with Cargo's home under different paths, built offline by `packaging/build-release.sh`; compares SHA-256 and searches the binary for home paths. First passed 2026-11-16 |

Because this is a security tool, it needs an outside review before you rely on it for anything sensitive: a classmate, a security-focused community review, or a small paid audit. Phase 6 is done, so this is due now; the Phase 6 security review in the roadmap (S12) does not replace it.
