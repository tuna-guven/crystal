# Testing and verification

Integration tests drive the real binary in a pseudo-terminal (`script`); their shared helpers are in `tests/common/mod.rs`. Tests of the shell and pager open a vault and add sample notes in memory with the debug-only flag `--demo-notes-for-test` (not in release builds, so those tests are ignored there; nothing is saved: the editor's Ctrl+S is refused in such a session, `demo_notes_are_never_saved`). Tests of the editor and of saving create real notes with `new` instead. Tests of startup steps 1 to 7, signals and the terminal guard pass the debug-only `--skip-unlock-for-test`, so they need no vault; release builds have no such flag. Under `cargo test --release`, the tests that need a debug-only hook are reported as ignored; everything else, including the tamper suite, runs against the release binary. Run it at the 512 MiB memlock floor too (`prlimit --memlock=536870912:536870912 cargo test --release`): only that run shows that the release binary's scrypt (log N 18, the same as every build; [decision 0027](../decisions/0027-scrypt-fixed.md)) fits in locked memory with everything else. Debug and test builds optimize the scrypt crates (`[profile.dev.package.*]` in Cargo.toml) so the integration tests stay fast.

Each security property gets a test that would fail if the property broke; tests run in CI on every commit.

| Test | What it proves | Tooling |
| --- | --- | --- |
| Property tests | Round trips (codec, padding, encryption); the editor's undo and redo restore every text exactly, its grapheme steps land on boundaries, any key sequence keeps its cursor and selection inside the text on grapheme boundaries, and its screen draws the cursor exactly once and spells out every hidden character, invisible ones inside a visible grapheme included (only an emoji keeps its joiner and U+FE0F); a name `new` accepts comes back exactly as typed; any sequence of saves, each failing at any step of the atomic writer or not at all, leaves memory equal to the vault (a save that reports nothing saved changed neither; 32 cases, as each opens a vault); the renderer, sanitizer, wrapping, names and key decoding never panic, never put a control or BiDi character on screen and never draw a line wider than the page | `proptest`: 256 cases per test on every `cargo test`; `scripts/long-tests.sh` runs a million per test for the text-handling modules and Crystal's age code (`age_v1`: round trips, flipped bits, truncation and extension, random input; about 21 minutes in all), weekly in CI (`.github/workflows/long-tests.yml`) and before releases |
| Tamper suite | A vault swapped in under another's name (pin), truncation, bit flips: all refused; an older generation opens only after the word `restore`, and anything else changes nothing | `tests/vault.rs`: each test makes a vault with `crystal init` through the real binary in a pty, damages one thing (vault or config truncated, bit-flipped, rolled back or swapped, a wrong passphrase, a missing `identity.age`, a writable parent, a sync conflict copy) and checks the fixed refusal |
| Coverage-guided fuzzing | No panics or hangs on hostile Markdown or vault bytes, beyond what random generation reaches | `cargo-fuzz` targets for render, sanitize and vault decode in a separate `fuzz/` crate; from Phase 6 (needs `libfuzzer-sys` and a nightly toolchain, to be approved then) |
| age v1 conformance | Crystal's own age code ([decision 0042](../decisions/0042-own-age-implementation.md)) reads and refuses files exactly as the reference implementations do, and what it writes is plain age | `tests/corpus/age-cctv/`: the C2SP/CCTV age vectors, unchanged (`scripts/import-cctv.sh`, pinned commit); `age_v1::cctv::cctv_age_vectors` runs the 92 for X25519, scrypt, the header and STREAM (armored and hybrid skipped) and re-encodes headers and payloads with the vectors' file keys. `tests/corpus/age-rage/`: files the `age` crate 0.11.5 wrote before step C3 removed it ([decision 0043](../decisions/0043-age-checked-against-stored-files.md); keys, passphrases and plaintext SHA-256 in `keys.txt` and `MANIFEST`, the generator in `SOURCE`): X25519 to one and three keys with age's grease, 0 bytes to 3 × 64 KiB, and scrypt identity files. `age_v1::rage` opens each with its keys and refuses strangers and wrong passphrases, and, under the unwrapped file key, re-encodes each file's stanzas (age's own, re-serialized), header MAC and STREAM payload to age's bytes; new stanzas cannot be compared byte for byte (their share or salt is random), so `wrap` is covered by the `wrapping_key` it shares with the checked `unwrap` and by the round trips; the `x25519`, `scrypt`, `header` and `crypto` tests use the same files. `age_v1::tests::round_trips_*` covers the same sizes and 32 MiB with Crystal alone (32 MiB is ignored in debug builds, a minute of unoptimized ChaCha20, and runs under `cargo test --release`). Integration tests check the real binary's files with its own commands (`check-code`, `recover`, unlock). By hand, once, 2026-11-09: Go age v1.3.2 opened a vault the binary wrote, and the binary unlocked a vault Go age wrote; no script repeats it |
| Escape-injection corpus | OSC 52, OSC 8, title changes, CSI, DCS, APC, 8-bit C1, BiDi, NUL, zero-width and overlong lines, in every Markdown context, render inert | `tests/corpus/escape/`: `md::render::tests::escape_corpus` checks every cell and compares with golden files (`UPDATE_GOLDEN=1` to accept a deliberate change) |
| Disk leak test | Inside the vault only ciphertext is written, and nothing else but the terminal (`/dev/pts`) (Phase 4 acceptance) | `strace_shows_only_ciphertext_written` (tests/vault.rs): `strace -f -yy -xx` over every write-family syscall (open, write and its vector and positional forms, sendfile, splice, rename, unlink, link, mkdir, truncate, fallocate) of a `new`, type, Ctrl+S session; every file opened for writing must be an atomic-writer temp file, only `write()` may reach a file, `mkdirat` may only find the state directory's levels already there, and each file's bytes, checked whole, must be an age file without the typed title or text canary in the vault, and only digits in the counter. Crystal is non-dumpable, so strace reads its bytes only with `CAP_SYS_PTRACE` (without it, it prints addresses) and its fd paths only with `CAP_DAC_READ_SEARCH` (its `/proc/PID/fd` is root's, mode 0500; without it, strace prints bare fd numbers); either way the test says so instead of passing unchecked. The test is therefore `#[ignore]`d and runs in CI only, which gives strace both capabilities (`setcap`) and runs it with `--ignored`; on secureblue it is not run (`deny_ptrace` stays on). Crystal itself gets no capability and keeps all of its hardening. `new_note_is_saved_and_opens_again` checks the finished files without strace |
| Crash during a save | `kill -9` at any moment of a save leaves a vault that opens, at the old or the new generation, with the counter never ahead (Phase 4 acceptance) | `kill_9_during_saves_never_corrupts_the_vault` (tests/vault.rs): at least 12 rounds of 300 saves, killed 0 to 330 ms after they start, and more (up to 60) until a kill has landed between the atomic writer's temp file and its rename, which a temp file left behind proves; about 40 s (here 4 of 12 kills land mid-write) |
| Canary scan | After lock, a unique canary string from a note no longer exists in process memory | Test-only feature that reads `/proc/self/mem` before dumpable is cleared |
| Hardening checks | Non-dumpable, no core, memory locked, no new privs | Integration test reading `/proc/self/status` |
| Sandbox checks | Denied syscalls kill the process; paths outside the vault return EACCES | Child-process tests through the debug-only `--sandbox-selftest CHECK`, one check per process ([Sandboxing](../design/sandboxing.md) section 9) |
| Unsafe code | The allocator is sound | `cargo miri test` on `zalloc` |
| Dependency audit | No known vulnerabilities, licenses allowed, crates reviewed | `cargo audit`, `cargo deny`, `cargo vet`, `cargo geiger` |
| Reproducibility | Same source gives the same binary | Two clean builds, compare SHA-256 |

Because this is a security tool, plan for an outside review once Phase 6 is done: a classmate, a security-focused community review, or a small paid audit before you rely on it for anything sensitive.
